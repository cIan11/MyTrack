# LifeTracker - Структурированный план проекта

## 1. Видение
LifeTracker - персональное iOS-приложение для управления задачами и временем по принципу Любищева.

Фокус текущего этапа:
- строго `single-user first` (для тебя);
- без перегруженной аналитики;
- максимально простой и понятный UX;
- основная ценность: ежедневная управляемость, а не красивые графики.

## 2. Продуктовые принципы
- Простота важнее "фичераздувания".
- 1 экран должен отвечать на вопрос "что делать прямо сейчас".
- Категория времени обязательна, задача - опциональна.
- Аналитика по умолчанию краткая; детализация открывается по запросу.
- Мягкие напоминания вместо давления дедлайнами.

## 3. Главный приоритет
Первый и основной модуль: **"Хронометраж + Ежедневник задач"**.

Все остальные идеи (расширенные привычки, глубокая аналитика, мультипользовательский режим) откладываются до стабильного MVP.

## 4. Целевая платформа и режим разработки
- Платформа: `iOS`.
- Стек запуска: Expo (как и планировалось).
- Режим данных на MVP: персональный аккаунт, подготовка к 1-нескольким пользователям без полноценного multi-tenant усложнения.

## 5. UX-концепция MVP

### 5.1 Информационная архитектура
1. `Home` - дашборд без перегруза.
2. `Tasks` - ежедневник задач.
3. `Timer` - быстрый запуск хронометража.
4. `Time Log` - лента интервалов за день.
5. `Summary` - краткая сводка + кнопка "показать детали".

### 5.2 Что видит пользователь на Home
- Профильный блок (приветствие, текущий день).
- Короткая сводка дня: выполнено задач, всего времени, остаток по задачам.
- "Огонек"/стрик дисциплины (по задачам и/или логам времени).
- Карточки модулей (Tasks, Timer, Summary) для быстрого входа.

Важно:
- Home не превращается в аналитический лист.
- Только 3-5 ключевых метрик, остальное внутри модулей.

### 5.3 Логика таймера
- При старте таймера пользователь **обязательно выбирает категорию**.
- Привязка к задаче:
  - либо сразу на старте;
  - либо позже при остановке/редактировании записи.
- Допустим сценарий "время без задачи" (например бытовые дела), но всегда с категорией.

### 5.4 Планирование задач
- Подход без жесткого time-blocking.
- Задачи ведутся списком с сортировкой по приоритету/сложности.
- Подзадачи - обычный чеклист.
- Приоритеты: `high`, `medium`, `low`, `none`.

### 5.5 Уведомления
- Нужны мягкие push-напоминания формата прогресса дня.
- Нужны напоминания "начать день".
- Не нужны навязчивые уведомления "останови таймер" и обязательное "ревью дня".

## 6. Scope MVP (что реализуем)

### 6.1 Tasks
- Создание/редактирование/архивация задач.
- Поля: название, заметка, приоритет, срок до (опционально), подзадачи.
- Статусы: `todo`, `in_progress`, `done`, `archived`.

### 6.2 Time Tracking
- Таймер start/stop.
- Ручное добавление интервалов.
- Обязательная категория.
- Привязка к задаче опциональна.
- Редактирование и удаление записей.

### 6.3 Summary
- Краткая дневная сводка: задачи выполнено/всего, план/факт по времени.
- Разбивка по категориям.
- Кнопка перехода в подробный вид.

## 7. Данные (черновая модель)
- `tasks` (priority включает `none`)
- `subtasks`
- `time_entries` (category required, task nullable)
- `categories` (предзаполненный пользовательский набор)
- `daily_stats`/`daily_reviews`

Базовые категории на старте:
- Работа
- Учеба
- Полезный досуг
- Дом
- Здоровье
- Потерянное время

## 8. Roadmap

### Phase 0 - Product Freeze (2-3 дня)
- Зафиксировать UX-потоки и экранные состояния.
- Утвердить минимальный набор метрик на Home.
- Утвердить тексты мягких уведомлений.

Результат:
- согласованный UX-spec без спорных зон.

### Phase 1 - Backend Core (4-6 дней)
- Миграции и модели Tasks/Time Entries/Categories.
- API задач, подзадач, таймера и дневной сводки.
- Валидации категорий и временных интервалов.

Результат:
- стабильный API для мобильного MVP.

### Phase 2 - iOS MVP UI (7-10 дней)
- Home, Tasks, Timer, Time Log, Summary.
- Быстрый пользовательский сценарий: открыть -> запустить таймер -> завершить задачу -> посмотреть сводку.

Результат:
- полностью рабочий MVP на iOS.

### Phase 3 - Stabilization (3-5 дней)
- Edge-cases, пустые состояния, UX-полировка.
- Базовые уведомления "начать день" и мягкий прогресс.

Результат:
- личная beta-версия для ежедневного использования.

## 9. Definition of Done для первого релиза
MVP готов, если ты можешь:
1. вести список задач с подзадачами и приоритетами;
2. запускать таймер с обязательной категорией;
3. логировать время с задачей или без задачи;
4. отмечать задачи выполненными;
5. видеть простую дневную сводку и стрик дисциплины.

## 10. Что откладываем на потом
- Расширенные отчеты и сложные графики.
- Интеграции календаря.
- Полноценный мультипользовательский режим и биллинг.
