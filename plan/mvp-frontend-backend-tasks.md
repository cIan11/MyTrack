# MVP Backlog (iOS, Single-User First)

## Контекст
Этот backlog собран под твой сценарий: личное iOS-приложение, минималистичный UX, без перегруза аналитикой.

## Product Rules (фиксируем как ТЗ)
- `iOS-first`.
- `single-user first` (архитектурно без блокировки роста до нескольких пользователей).
- В таймере категория обязательна.
- Привязка к задаче опциональна.
- Уведомления только мягкие (прогресс дня, старт дня).
- Приоритеты задач: `high`, `medium`, `low`, `none`.
- Подзадачи: только чеклист.

## Backend Tasks

### BE-01. DB schema для MVP
- [ ] Таблицы: `tasks`, `subtasks`, `time_entries`, `categories`, `daily_stats`.
- [ ] Индексы: `tasks(user_id,status,due_at)`, `time_entries(user_id,start_at)`.
- [ ] Enum/check constraints для статусов, приоритетов, категорий активности.
Критерий готовности:
- [ ] Миграции проходят up/down без ошибок.

### BE-02. Seed категорий по умолчанию
- [ ] Добавить стартовые категории: Работа, Учеба, Полезный досуг, Дом, Здоровье, Потерянное время.
- [ ] Запретить удаление категории, если на нее есть ссылки.
Критерий готовности:
- [ ] Новый пользователь сразу видит готовый набор категорий.

### BE-03. API задач
- [ ] `POST /tasks`
- [ ] `GET /tasks` (today, overdue, done, all)
- [ ] `GET /tasks/:id`
- [ ] `PATCH /tasks/:id`
- [ ] `PATCH /tasks/:id/status`
- [ ] `DELETE /tasks/:id` (soft delete)
Критерий готовности:
- [ ] Поддержан приоритет `none` и чеклист подзадач.

### BE-04. API подзадач
- [ ] `POST /tasks/:taskId/subtasks`
- [ ] `PATCH /subtasks/:id`
- [ ] `PATCH /subtasks/:id/toggle`
- [ ] `DELETE /subtasks/:id`
Критерий готовности:
- [ ] Подзадачи корректно отражаются в деталях задачи.

### BE-05. API таймера
- [ ] `POST /timer/start` (category required, task optional)
- [ ] `POST /timer/stop`
- [ ] `GET /timer/active`
Критерий готовности:
- [ ] В один момент времени только один активный таймер.

### BE-06. API time entries
- [ ] `POST /time-entries` (ручной ввод)
- [ ] `GET /time-entries` (по дате/диапазону)
- [ ] `PATCH /time-entries/:id`
- [ ] `DELETE /time-entries/:id`
Критерий готовности:
- [ ] Нельзя создать запись без категории.

### BE-07. API summary
- [ ] `GET /summary/daily?date=YYYY-MM-DD`
- [ ] Возвращать: задачи выполнено/всего, минуты по категориям, план/факт.
- [ ] `GET /summary/home?date=YYYY-MM-DD` для короткой Home-сводки.
Критерий готовности:
- [ ] Home получает легкий payload без тяжелой аналитики.

### BE-08. Edge-cases
- [ ] Пересекающиеся интервалы.
- [ ] Переход через полночь.
- [ ] Незавершенный таймер после перезапуска клиента.
Критерий готовности:
- [ ] Все edge-cases покрыты тестами.

### BE-09. Уведомления (серверная часть)
- [ ] Эндпоинт/джоба для мягкого напоминания "начать день".
- [ ] Эндпоинт/джоба для мягкого прогресс-пинга (например "6/7 задач").
Критерий готовности:
- [ ] Нет агрессивных/частых пушей.

## Frontend Tasks (iOS / Expo)

### FE-01. App shell и навигация
- [ ] Табы/навигация: `Home`, `Tasks`, `Timer`, `Log`, `Summary`.
- [ ] Глобальная плашка активного таймера.
Критерий готовности:
- [ ] Любой ключевой экран открывается без сбоев.

### FE-02. Home (минималистичный дашборд)
- [ ] Профильный блок.
- [ ] Короткая сводка дня (3-5 метрик).
- [ ] Стрик/"огонек" дисциплины.
- [ ] Карточки быстрого перехода в модули.
Критерий готовности:
- [ ] Home не превращается в аналитическую простыню.

### FE-03. Tasks list
- [ ] Фильтры: today, overdue, all, done.
- [x] Сортировка по приоритету и сроку.
- [x] Быстрое завершение задачи.
Критерий готовности:
- [ ] Планирование дня делается в 1-2 минуты.

### FE-04. Task details
- [x] Редактирование полей задачи.
- [x] Подзадачи-чеклист.
- [x] Заметки.
- [ ] Отображение фактически потраченного времени.
Критерий готовности:
- [ ] Управление задачей в одном месте.

### FE-05. Timer flow
- [x] Старт с обязательным выбором категории.
- [x] Выбор задачи опционален.
- [ ] Стоп с возможностью допривязать задачу.
Критерий готовности:
- [ ] Пользователь не блокируется, если задача не создана заранее.

### FE-06. Time Log
- [ ] Лента интервалов за день.
- [ ] Редактирование/удаление.
- [ ] Ручное добавление интервала.
Критерий готовности:
- [ ] Можно быстро восстановить день задним числом.

### FE-07. Summary
- [ ] Краткая сводка дня.
- [ ] Кнопка "подробнее" для детального вида.
- [ ] Простая визуализация категорий.
Критерий готовности:
- [ ] Сначала кратко, детали только по запросу.

### FE-08. Уведомления UX
- [ ] Экран настроек уведомлений (on/off для мягких напоминаний).
- [ ] Тексты уведомлений в дружелюбном стиле.
Критерий готовности:
- [ ] Нет ощущения давления от приложения.

### FE-09. UI Polishing
- [ ] Минималистичный визуальный стиль.
- [ ] Пустые состояния без перегруза.
- [ ] Единая типографика и ритм отступов.
Критерий готовности:
- [ ] Интерфейс аккуратный и легкий для ежедневного использования.

### FE-10. Тесты
- [ ] Критический e2e-сценарий: Home -> Timer -> Tasks -> Summary.
- [ ] Unit-тесты форм создания задачи и time-entry.
Критерий готовности:
- [ ] Основной поток защищен автотестами.

## Порядок реализации
1. BE-01 -> BE-03 -> BE-05 -> BE-07
2. FE-01 -> FE-02 -> FE-05 -> FE-03 -> FE-04
3. FE-06 -> FE-07 -> BE-08
4. FE-08 -> FE-09 -> FE-10 + BE-09

## Release DoD
- [ ] Задачи, подзадачи, приоритеты и мягкие дедлайны работают.
- [ ] Таймер запускается только с категорией.
- [ ] Время можно логировать и с задачей, и без задачи.
- [ ] Home показывает короткую полезную картину дня.
- [ ] Summary дает краткий и детальный режим.
